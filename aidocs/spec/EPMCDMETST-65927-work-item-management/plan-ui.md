# Implementation Plan: Work Item Management (codemie-ui-next)

## Overview
This plan covers the **Front-end UI** implementation for the Work Item Management feature, a new task/ticket management system within CodeMie. This feature allows users to create, view, filter, and sort work items within project-scoped contexts.

**Repository**: codemie-ui-next

## User Story
**As a** platform user,  
**I want to** create, view, and manage work items with filtering and sorting capabilities,  
**so that** I can effectively track and organize platform activities.

### Acceptance Criteria
1. Users can create a new work item with all required fields (Title, Description, Type, Priority, Status, Assignee, Tags)
2. Users can view a list of all work items in a structured table/card view
3. Users can filter work items by Type, Priority, and Status (independently or combined)
4. Users can sort work items by Priority, Created Date, or Updated Date (ascending/descending)
5. Work item data persists correctly in the backend database
6. API endpoints support CRUD operations and filtering/sorting with appropriate response codes
7. UI provides clear feedback for successful operations and validation errors

### Assumptions
- Work item fields use predefined enum values for Type, Priority, and Status
- Assignee field references existing project members (accessed via project members API)
- Tags are free-text, comma-separated values
- Def5ault sort order is by Created Date (descending)
- Work items are project-scoped (belong to a specific project)
- Default field values: Type=Task, Priority=Medium, Status=Open, Assignee=empty
- Created Date & Updated Date are auto-generated by backend

## Architecture & Design

### Component Overview

**Main Components**:
1. **WorkItemsPage** (`src/pages/workItems/WorkItemsPage.tsx`):
   - Main list page with table, filters, and create button
   - Uses `useTableFilters` hook for sort, pagination, filters
   - Consumes `workItemStore` via `useSnapshot`
   - Renders `Table` component with column definitions

2. **WorkItemFilters** (`src/pages/workItems/components/WorkItemFilters.tsx`):
   - Sidebar filters for Type, Priority, Status
   - Uses `Filters` component with `FilterDefinitionType.Multiselect`
   - Persists filters to localStorage via `FILTER_ENTITY.WORK_ITEMS`

3. **WorkItemForm** (`src/pages/workItems/components/WorkItemForm.tsx`):
   - Form for creating/editing work items
   - Fields: Title (`Input`), Description (`TextArea`), Type (`Select`), Priority (`Select`), Status (`Select`), Assignee (`Select` from project members), Tags (`Input`)
   - Client-side validation: required fields, max length
   - Displayed in `Modal` or dedicated page

4. **WorkItemStatusBadge** (`src/pages/workItems/components/WorkItemStatusBadge.tsx`):
   - Custom renderer for status column with color coding
   - Maps status values to badge colors (e.g., Open as gray, In Progress as blue, Done as green)

5. **WorkItemPriorityBadge** (`src/pages/workItems/components/WorkItemPriorityBadge.tsx`):
   - Custom renderer for priority column with color coding
   - Maps priority values to badge colors (e.g., Critical as red, High as orange, Medium as yellow, Low as gray)

6. **WorkItemActions** (`src/pages/workItems/components/WorkItemActions.tsx`):
   - Actions column renderer: Edit, Delete buttons
   - Opens edit modal or routes to edit page
   - Delete confirmation dialog

7. **WorkItemStore** (`src/store/workItems.ts`):
   - Valtio proxy store for work item data
   - Methods: `indexItems`, `createItem`, `updateItem`, `deleteItem`, `getItemById`
   - State: `items`, `pagination`, `loading`, `error`

8. **Types** (`src/types/entity/workItem.ts`):
   - `WorkItem`, `WorkItemCreateRequest`, `WorkItemUpdateRequest` interfaces
   - `WorkItemType`, `WorkItemPriority`, `WorkItemStatus` enums

9. **Constants** (`src/constants/workItems.ts`):
   - `WORK_ITEM_TYPES`, `WORK_ITEM_PRIORITIESF, WORK_ITEM_STATUSES` arrays for dropdowns
   - `DEFAULT_PER_PAGE`, `FILTER_ENTITY.WORK_ITEMS`

### Security Considerations
- **Authentication**: Use existing CodeMie authentication (token from `userStore`)
- **Authorization**: Project-level access: only project members can view/create/edit/delete work items
- **Input Validation**: Client-side validation for required fields, max lengths, enum values
- **Error Handling**: Display user-friendly error messages from API responses (`@/utils/toaster`)
- **XSS Prevention**: Sanitize user input (strings) before rendering (use React's default escaping)

### Error Handling

**Store Error Pattern**:
```typescript
try {
  const response = await api.post(`...`)
  const data = await response.json()
  // update state
} catch (error: any) {
  const contextualError = error.response?.data?.message ?? error.message
  this.error = `Failed to create work item: ${contextualError}`
  console.error('WorkItemStore Error (createItem):', error)
  toaster.error(this.error)
  throw error
} finally {
  this.loading = false
}
```

**UI Error Display**:
- Form validation errors: Render below each field with `className="text-text-error"`
- API errors: Display via `toaster.error()`
- Loading state: Show `LoadingSpinner` component
- Empty state: Display "No work items found. Create one to get started!"
